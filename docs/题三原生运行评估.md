# 题三（Isaac Sim 玩具触碰）脱离 Docker 原生运行可行性评估

实测时间：2026-11-20 21:20（UTC+8）
评估对象：`bajie-demo/src/question3_project/`，当前经 `run_laptop.sh` 在 `bajie/sim:humble45` 容器内运行。

## 结论

技术路径存在，但在**当前这台笔记本上不可行**，三道卡点按严重度排列：

1. **磁盘**：剩余 15 GiB，Isaac Sim 4.5 解压后本体实测 14 GiB，加缓存与余量需 ≥22 GiB。
2. **ROS 发行版**：宿主机只有 Jazzy（Python 3.12），Isaac Sim 4.5 的 `isaacsim.ros2.bridge` 只带 Humble 内部库；Jazzy 支持从 5.0 才有。
3. **系统版本**：宿主机 Ubuntu 24.04，Isaac Sim 4.5 官方支持矩阵为 22.04。

现有 Docker 方案已完整跑通（三例接触成功，日志见 `bajie-demo/assets/q3_run.log`），不建议为"脱离 Docker"这一形式目标承担上述三项改造风险。

## 一、本机实测与 4.5 原生要求的差距

| 项目 | 本机实测 | Isaac Sim 4.5 原生要求 | 判定 |
| --- | --- | --- | --- |
| 操作系统 | Ubuntu 24.04.5 LTS | 官方支持 22.04 | 不符，24.04 至今不在 4.5 支持矩阵 |
| ROS 2 | `/opt/ros/jazzy`，Python 3.12 | 4.5 的 bridge 内置库仅 Humble | 硬缺 |
| Python | 系统 3.12.3 | zip 包自带 3.10 运行时；但 rclpy 必须与 3.10 ABI 一致 | 需 Humble（py3.10） |
| NVIDIA 驱动 | 580.178.04 | ≥535 且 ≤580 | 符合 |
| GPU | RTX 4060 Max-Q，8 GiB | ≥8 GiB，推荐 16 GiB | 处于下限 |
| 磁盘 | 根分区 196 GiB 已用 93%，可用 15 GiB | `/isaac-sim` 解压实测 14 GiB | 缺约 8 GiB |
| 容器工具链 | Docker 29.10.0，镜像已就绪 | — | 已具备且验证通过 |

磁盘可回收量实测：`docker system df` 显示 Build Cache 26.44 GiB 中可回收 2.108 GiB、Image 可回收 175 MiB，合计约 2.3 GiB。清理后可用约 17 GiB，仍低于 22 GiB 的需求。

## 二、四条候选路线

| 路线 | 做法 | 空间需求 | 主要障碍 | 工作量 |
| --- | --- | --- | --- | --- |
| A | 官方 standalone zip 原生安装 | 7.2 GiB 下载 + 14 GiB 解压 ≈ 21 GiB | 磁盘缺 8 GiB；24.04 非支持版本；需另装 Humble | 大 |
| B | 升级 Isaac Sim 5.x 原生 | 15–20 GiB | 题面明确要求 4.5；5.x 改了 joint state 节点与 experimental API，三例需重跑重录 | 大 |
| C | 从现有镜像移植 `/isaac-sim`（14 GiB）+ `/opt/ros/humble`（121 MiB） | 14.2 GiB | 当前 15 GiB 极限可行但零余量；缺 `.so` 风险需逐项核对 | 中 |
| D | 维持 Docker（现状） | 0 | 无 | 无 |

路线 A 的下载地址实测可达（HTTP 200，`content-length: 7208817125`），并非被阻断，卡点纯粹在本地空间与 ROS 发行版。

## 三、走原生路线必须改动的写死假设

以下位置把容器布局当成了不变前提，原生运行时需逐条替换：

| 位置 | 现状 | 原生需改成 |
| --- | --- | --- |
| `run_touch.py:267` | `ISAAC_PATH` 默认 `/isaac-sim` | 指向解压目录，或导出环境变量 |
| `run_touch.py:279-280` | `--ext-folder` 依次指向 `exts`/`extscache`/`extsPhysics`/`extsDeprecated` | standalone 包布局相同，改 `ISAAC_PATH` 即可连带生效 |
| `run_touch.py:270-271` | GUI 用 `apps/isaacsim.exp.base.kit`，无 GUI 用 `physics.kit` | 同上，路径随 `ISAAC_PATH` 派生 |
| `physics.kit` | `app.extensions.registryEnabled=false` 依赖上述 `--ext-folder` | 不改，但缺 `--ext-folder` 时扩展解析直接失败 |
| `run_laptop.sh` | `source /opt/ros/humble/setup.bash` | 宿主机必须存在 Humble，noble 无 apt 包 |
| `run_laptop.sh` | `--tmpfs /isaac-sim/kit/cache` 提供可写缓存 | 原生目录本身可写，此条可去掉（这条是简化） |
| `run_laptop.sh` | `--user $(id -u)`、`ROS_LOCALHOST_ONLY`、`ROS_DOMAIN_ID=53` | 原生时由当前用户直接继承，仍建议保留 domain 隔离 |

关键 ABI 约束：`run_touch.py` 在 Isaac 自带 Python 3.10 进程内 `import rclpy`。Humble 的 `rclpy` 编译于 Python 3.10，与本机 Jazzy 的 Python 3.12 版本不兼容，因此在宿主机只装 Jazzy 无法让该导入成立。这也是路线 A/C 都必须解决 Humble 的根本原因，而 Humble 官方 apt 源仅覆盖 jammy。

## 四、建议

1. **默认维持路线 D**。Docker 方案已产出可复现日志与作答，评审按 README 执行也最稳。
2. **确需脱离 Docker 时，先解决空间再谈路线**：清理构建缓存可回收约 2.3 GiB，仍不够，需要通过删除历史镜像或扩容释放至少 8 GiB。
3. 空间到位后推荐 **路线 C**（省掉 7.2 GiB 下载），执行顺序为：导出目录 → `ldd` 全量核对依赖 → 改 `ISAAC_PATH` → 单例 `--case rubik_cube` 验证 → 三例全跑。
4. 路线 B 需要先确认题面是否允许 5.x，当前题面写明"题目三使用 Isaac Sim 4.5 和 ROS 2 Bridge"。
