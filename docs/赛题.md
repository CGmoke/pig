## 二、初赛题目

### 2.1 通用数据格式

* 输入和输出采用 JSONL，每行一个完整的 JSON 对象。复制下方的多行示例时，将单个对象压缩到一行。
* 每个测例以 `id` 标识，输出沿用输入的 `id`。
* 完整关节状态包含 `lift_joint`、`pitch_joint`、`joint1` 至 `joint6`、`arm_finger_joint1` 和 `arm_finger_joint2`。升降位置以米为单位，旋转关节角以弧度为单位。
* `base_footprint` 表示底盘坐标系，`objects_link` 表示夹爪的抓取参考坐标系。位姿中的 `xyz` 以米为单位，`rpy` 依次为滚转、俯仰和偏航角，以弧度为单位。四元数 `quat_xyzw` 的顺序为 `[x, y, z, w]`。

### 2.2 题目一 · 关节分步驱动与 RViz 展示

**题目目标**

按顺序驱动升降关节 `lift_joint`、头部关节 `pitch_joint`、机械臂关节 `joint1` 至 `joint6`，最后控制夹爪先张开再闭合。机器人运动应在 RViz 中可见，并记录每一步完成时的完整关节状态。

升降、头部和机械臂各阶段完成后等待 `pause_sec`，默认 5 秒。

**输入（`q1_demo_input.jsonl`）**

`step` 取 `all`，执行完整流程。`seed` 为随机种子，`move_sec` 和 `pause_sec` 的单位为秒。

```json
{"id": "q1_all_seed7", "step": "all", "seed": 7, "move_sec": 3.0, "pause_sec": 5.0}
```

**输出（`q1_demo_output.jsonl`）**

输出包含 `id`、`step`、`keyframes` 和 `final_joint_state`。`keyframes` 中的 `name` 按 `lift` → `head` → `arm` → `gripper_open` → `gripper_close` 排列，每项的 `joint_state` 须包含全部 10 个关节。`final_joint_state` 记录流程结束时的关节状态。

### 2.3 题目二 · 正向运动学与坐标变换

**题目目标**

1. 根据输入的完整 `joint_state` 做正向运动学，求 `objects_link` 相对 `base_footprint` 的位姿。
2. 将场景物体在 `base_footprint` 坐标系中的位姿变换到 `objects_link` 坐标系。

**输入（`q2_demo_input.jsonl`）**

`scene_object_in_base_footprint` 给出场景物体相对底盘的位姿。示例中，物体位于底盘前方 0.5 米、右侧 0.5 米、高 0.3 米，姿态为单位旋转。

### 2.4 题目三 · 在 Isaac Sim 中触碰玩具

### 3.2 材料要求

* `README.md` 写明作品名称、参赛者或团队、功能与创新点、依赖版本、各题启动命令、执行目录、输入输出路径和复现步骤。评审会通过 AI 读取运行说明、执行作品并评分。
* `src/` 提供三道题的完整可运行代码及所需配置。外部依赖或模型应注明版本和获取方式。
* `inputs/` 保存题目给定的测例，`answers/` 保存逐个测例的 JSONL 作答结果。
* `assets/` 提供各题终端的完整 `.log` 日志及其他辅助素材。模型、数据集等大体积依赖可在作品 README 中附上可访问链接、版本、用途和访问条件。
* `video/` 上传作品演示视频， **单个视频文件大小不超过 30 MB（30,000,000 字节）** 。须提供题目一的 RViz 演示视频和题目三的 Isaac Sim 触碰视频，题目二视频可选。作品 README 中注明视频文件名及对应题目。
* 提交前检查材料范围，仅提交自己的作品目录。移除密钥、访问令牌、个人隐私数据和无权公开的材料。

提交前按本节材料要求逐项自查。运行说明的写法可参考[初赛作品示例](https://atomgit.com/ecovacs-bajie/ecovacs-bajie-competition/blob/main/bajie-demo/README.md)。

### 3.3 视频格式与压缩建议

* 建议使用  **MP4 容器、H.264 视频编码和 AAC 音频编码** ，便于评审在常见播放环境中查看。希望提高压缩效率时，可使用  **MP4 + H.265（HEVC）** ，并提前确认评审环境支持播放。压缩效率主要由编码方式及参数决定。[视频编码说明](https://handbrake.fr/docs/en/latest/technical/video-codecs.html)
* 可从 **720p、25 或 30 fps** 开始压缩，保留清楚可辨的关节运动、触碰过程和关键结果。旁白音频可采用  **64–96 kbps AAC** ，最终参数按实际画面清晰度调整。
* 为控制文件大小，可在 HandBrake 中选择平均码率并开启多次编码。建议将目标大小留在约  **27 MB** ，导出后核对实际文件大小是否符合 30 MB 上限。[码率与文件大小说明](https://handbrake.fr/docs/en/latest/technical/video-cq-vs-abr.html)
* 可按 `文件大小（MB）≈ 总码率（Mbps）× 时长（秒）÷ 8` 估算。例如，2 分钟视频采用约  **1.8 Mbps 总码率** ，音视频数据约为  **27 MB** ；总码率需计入音频，并为容器等开销留出余量。
